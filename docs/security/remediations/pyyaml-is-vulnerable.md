# PyYAML is vulnerable

**Issue:** #60  
**Severity:** Critical  
**CWE:** CWE-502: Deserialization of Untrusted Data  
**CVEs:** CVE-2020-14343, CVE-2020-1747

## Summary

This repository depends on `pyyaml==5.3.1`, which is affected by a critical deserialization weakness. Versions before 5.4 can execute attacker-controlled code when untrusted YAML is processed with `yaml.load()` using `FullLoader`/`full_load`-style parsing paths.

## Why this matters

A malicious YAML document can abuse Python object construction tags such as `python/object/new` to trigger arbitrary code execution. In a real application, that can lead to full compromise of the process handling the upload or configuration file.

## Recommended remediation

- Upgrade PyYAML to a fixed version (`>= 5.4`, preferably the latest supported release).
- Replace any unsafe YAML parsing with `yaml.safe_load()` or another schema-restricted parser.
- Treat all user-controlled YAML as untrusted input and validate the resulting structure before use.

### Non-applied code suggestion

```python
import yaml

# NOT APPLIED: suggested remediation only
parsed = yaml.safe_load(untrusted_yaml)
```

If object construction is genuinely required, use an explicit allowlist and a narrowly scoped loader instead of `FullLoader` or raw `load()`.
